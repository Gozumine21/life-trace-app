# 基本設計書 — LifeTrace

## 1. システム構成概要

```
[Flutter App (iOS/Android)]
        │
        ▼
[Firebase Authentication]  … ユーザー認証
[Cloud Firestore]          … ライフイベント・ユーザー・コメント等のデータ保存
[Firebase Storage]         … 画像・アイコンの保存
[Cloud Functions]          … 通知・集計・モデレーション等のサーバーサイド処理
[Firebase Cloud Messaging] … プッシュ通知
```

- クライアント：Flutter（Dart）。状態管理は Riverpod を採用。
- バックエンド：Firebase（サーバーレス構成、独自APIサーバーは持たない）
- データベース：Cloud Firestore（NoSQL ドキュメント指向DB）

## 5. 主要機能の設計方針

### 5.1 ライフイベント入力
- 入力後は Cloud Firestore の `lifeEvents` コレクションにドキュメントとして保存
- 画像は Firebase Storage にアップロードし、URLのみ Firestore に保存
- 感情タグは事前定義のEnum＋スコア値（-5〜+5）を持たせ、グラフ描画に利用

### 5.2 可視化（感情グラフ）
- ユーザーのライフイベントを発生年月でソートし、感情スコアを `fl_chart` の折れ線グラフにプロット
- カテゴリ別件数は集計してパイチャート表示

### 5.3 追体験モード
- 対象ユーザーのライフイベントを時系列順に取得し、PageView で1件ずつ表示
- スワイプで次のイベントへ。各ページに「いいね／共感スタンプ」ボタンを配置
- 閲覧履歴を `experienceLogs` コレクションに記録し、レコメンドに利用（将来拡張）

### 5.4 公開範囲制御
- ライフイベントに `visibility` フィールド（public / followers / private）を保持
- Firestore Security Rules でクライアント側からの不正な読み取りを防止
- 非公開データの判定はすべてセキュリティルールで強制し、クライアントロジックに依存しない

### 5.5 通知
- いいね・コメント・新規投稿イベントを Cloud Functions の Firestore トリガーで検知
- FCM経由でプッシュ通知を送信し、`notifications` コレクションにも履歴を保存

## 7. セキュリティ設計概要

- すべてのFirestoreアクセスはFirebase Authのトークンを前提とし、未認証アクセスは拒否
- Firestore Security Rulesにて、`visibility` フィールドに基づくドキュメント単位のアクセス制御を実装
- 画像アップロードはFirebase Storageルールでファイルサイズ・形式を制限
- センシティブワードの簡易フィルタリングをCloud Functionsで実施（将来、モデレーション機能へ拡張）
